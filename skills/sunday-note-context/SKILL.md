# 个人上下文

## 工作流

1. 读取根目录 `个人上下文.md` 和 `AGENTS.md`。无已确认正文时初始化，否则只校准指定部分。
2. 读取用户给出的准确项目、记录入口或现有汇总、Wiki 和索引，提取稳定职责、关系、检索词；已有可靠答案不再询问。
3. 按下方主题逐题访谈，每次只问一个尚无可靠答案且可能产生个人增量的问题。已有内容或本轮回答覆盖时跳过；允许跳过、提前结束和取消。回答矛盾或无法提炼时追加澄清，整个访谈最多追加两题，主题问题不计入此上限。
4. 按增量条件筛选内容，使用 `assets/个人上下文.md` 生成完整页面，并提炼完整个性化响应段；同时展示两份草案。
5. 用户要求修改时更新并重新展示两份草案；一次明确确认两份完整草案后才同时写入。

## 问题

按顺序询问缺失信息，不提前展示后续问题。只重复默认行为的回答不保存。

### 兴趣与经验

#### 1. 长期任务

> 未来三到六个月，你反复讨论、亲自负责或持续建设的 2–4 类任务或项目是什么？为什么值得投入？哪些方向只关注而不直接参与？

#### 2. 非项目长期兴趣

> 项目之外，哪些长期兴趣会影响你的阅读、检索、推荐或分析？你主要关注什么问题？

### 价值取舍

#### 3. 跨领域核心原则

> 跨越具体项目和近期议题，什么原则反复指导你的选择？你希望长期增加、减少、维护或推动什么？

#### 4. 跨领域验证

> 举两个不同领域的例子，说明这条原则如何改变选择。只适用于单个项目或议题的取舍留在对应项目或 Wiki。

### 证据与知识演化

#### 5. 非默认的证据处理

> 处理证据冲突、信息不足或停止调查时，你有什么不同于按证据强度、决策影响和调查成本判断的稳定要求？没有可跳过；有则说明何时改变判断。

### 判断与协作

#### 6. 非默认的协作边界

> 在 Agent 按风险、可逆性和当前授权推进的基础上，你希望在哪些条件下更主动或更保守？没有特殊要求可跳过。

### 表达偏好

#### 7. 直接程度与选项

> 你更愿意读 A「这个方案值得做；先把范围缩小到一周内可验证的版本」，还是 B「这个方案可以考虑；或许先把范围缩小到一周内可验证的版本」？为什么？默认给一个推荐还是同时给备选？

#### 8. 术语密度

> 你更愿意读 A「先做小范围测试，确认结论在不同情况下都成立，再扩大使用」，还是 B「先做局部验证，确认结论具备跨情境稳健性，再扩大应用」？为什么？选择随任务变化时请说明分界。

## 增量条件

只保存稳定、已确认，且提供未知个人事实或入口、或会改变未来同类任务检索、取舍、行动或表达的信息。删除后不影响后续任务的内容省略。

- 通用能力和根规则已有要求不重复保存；个人偏好只记录差异及适用情境、默认选择和可观察的切换条件。条件含糊时澄清或省略。
- 项目保存稳定职责、长期关系和入口，不保存进度、里程碑和短期计划。本人项目默认按熟悉者交流；只关注、参与有限或正在入门时记录例外，不扩展到其他主题。
- 长期兴趣不自动代表专业经验；单个案例不扩展为全局偏好。
- 不保存访谈流水、评分、人格判断、临时情绪或未经确认的推断。个人偏好不改变来源事实、安全约束和 vault 权限。

## 输出与写入

`个人上下文.md` 保留模板的五章标题，章节无增量时留空；正文仅含通过筛选的信息、实际页面链接和检索词。

个性化响应段仅保留跨任务生效的个人行为差异，不复述项目、兴趣或通用表达要求：

```markdown
## 个性化响应

<一行且不换行的行为 prompt 段落>

仅在当前任务需要进一步了解个人长期项目、取舍或表达偏好时，再读取：
- [[个人上下文]]
```

上述结构只用于个人上下文产物，不作为日常回答格式。

- 根 `AGENTS.md` 无 `## 个性化响应` 时在末尾追加；恰有一个时替换该标题至文件末尾；重复时停止。
- 任一文件无法安全修改时，两份都不写。取消、沉默或含糊确认不写入；普通风格反馈不自动积累。
