# 个人上下文

## 工作流

1. 读取根目录 `个人上下文.md` 和 `AGENTS.md`。页面没有已确认正文时执行初始化；已有内容时只校准用户指定的部分。
2. 以模型通用能力、系统约束和根规则为默认基线，只保留通过增量检查的个人信息。
3. 对用户列出的长期项目和记录入口，读取用户给出的准确页面或现有项目汇总、Wiki 和索引，提取稳定职责、关系、检索词和入口；不重复询问已有可靠答案，不把页面中的当前进度写入个人上下文。
4. 按兴趣与经验、价值取舍、证据与知识演化、判断与协作、表达偏好依次访谈。每轮只展示一个尚无可靠答案且可能产生个人增量的问题；已有内容或本轮回答已经明确覆盖时跳过。允许跳过、提前结束或取消；只在回答矛盾或无法提炼时追加澄清，整轮最多两题。
5. 使用 `assets/个人上下文.md` 的完整结构生成个人上下文，并从中提炼一段个性化响应 prompt。逐条执行增量检查后，同时展示完整页面和完整个性化响应段。
6. 用户提出修改时重新生成两份草案；只有用户一次明确确认两份完整草案后才同时写入。

## 问题

按下列顺序只询问尚无可靠答案的问题，不要提前展示后续问题。回答只重复 agent 默认行为时不写入，直接继续下一题。

### 兴趣与经验

#### 1. 长期任务

> 未来三到六个月，你最可能反复讨论、亲自负责或持续建设的 2–4 类真实任务或项目是什么？为什么它们值得长期投入？如果其中有你只关注而不直接参与的方向，请一并说明。

#### 2. 非项目长期兴趣

> 除上述项目外，你还长期关注哪些业余方向，例如历史、哲学、科学、文学、艺术或宗教？请选择未来仍会影响阅读、检索、推荐或分析的方向，并说明你主要关心其中什么问题；不必列举短期好奇。

### 价值取舍

#### 3. 跨领域核心原则

> 抛开具体项目、近期任务和单一议题，在知识、工作、生活或社会判断中，是否有反复指导你选择的上位原则？请用一句话说明你希望长期增加、减少、维护或推动什么。

#### 4. 跨领域验证

> 请举两个不同领域的例子，说明这条原则怎样改变你的判断或选择。如果它只适用于某个项目或单一议题，就把它保留在对应项目或 Wiki，而不作为个人核心价值。

### 证据与知识演化

#### 5. 非默认的证据处理

> 对证据冲突、信息不足和调查停止，你是否有不同于通常基于证据强度、决策影响和调查成本处理的稳定要求？没有特殊要求可以直接跳过；有的话请说明它会在哪些情况下改变判断或输出。

### 判断与协作

#### 6. 非默认的协作边界

> 在 agent 通常会按风险、可逆性和当前授权自主推进，并在关键价值条件缺失时询问你的基础上，你是否希望我更主动或更保守？没有特殊要求可以跳过；有的话请给出会改变行动的分界条件。

### 表达偏好

#### 7. 直接程度与选项

> 下面两句只比较直接程度，你更愿意读哪一句？A「这个方案值得做；先把范围缩小到一周内可验证的版本」；B「这个方案可以考虑；或许先把范围缩小到一周内可验证的版本」。请说明原因，并说明你希望我默认只给一个推荐，还是同时给出备选方案。

#### 8. 术语密度

> 下面两句只比较术语密度，你更愿意读哪一句？A「先做小范围测试，确认结论在不同情况下都成立，再扩大使用」；B「先做局部验证，确认结论具备跨情境稳健性，再扩大应用」。请说明原因；如果选择取决于任务，也请给出分界线。

这些问题只用于提炼用户明确表达的长期增量。不计算分数，不诊断人格，不根据示例选项或项目内容推断用户没有说明的价值偏好；系统安全、事实真实性和 vault 权限不随个人偏好改变。

## 增量检查

每条候选内容依次检查：

1. 是否稳定、已确认，而非当前任务中的临时要求？
2. 是否提供模型无法自行知道的个人事实或入口，或者会使 agent 相对通用能力和根规则稳定地改变检索、取舍、行动或表达？
3. 如果删除这一条，未来同类任务的回答是否可能实质不同？

任一答案为否则不写。通用事实处理、风险意识和当前请求优先等默认能力或根规则已有要求不写；用户明确要求不同边界时只保存差异。

## 输出

`个人上下文.md` 使用 `assets/个人上下文.md` 的全部标题，并遵循以下规则：

- 只保存通过增量检查的简练信息，以及实际存在的页面链接和检索词；章节没有增量时保留标题，不为填满结构而生成内容。
- 本人长期项目默认按熟悉项目处理，只对个人上下文中列出的项目生效；不询问或单独保存“是否熟悉”。用户明确表示只关注、参与有限或正在入门时才记录例外。
- 非项目兴趣只保留会长期影响阅读、检索、推荐或分析的方向，不把业余兴趣默认视为专业经验。
- 项目只保留稳定职责、长期关系和入口，不保存当前进度、里程碑、短期计划或容易过时的状态。
- 个人取舍和非默认偏好在需要时写清适用情境、默认选择和可观察的切换条件；无法操作化的“尽可能”“重要时”“必要时”“适当”等表述应澄清或省略。
- 不保存访谈流水、题号、评分、临时情绪、心理标签或未经确认的推断；不把单个案例中的选择扩展为全部任务的全局偏好。

个性化响应段使用以下结构：

```markdown
## 个性化响应

<一行且不换行的行为 prompt 段落>

仅在当前任务需要进一步了解个人长期项目、取舍或表达偏好时，再读取：
- [[个人上下文]]
```

prompt 只保留会跨任务改变回答方式的个人增量，不复述兴趣列表、项目介绍、个人画像、agent 默认能力或根规则。个人上下文按下方说明按需读取。对其中列出的本人项目，直接基于已有项目上下文继续讨论，不扩展到其他主题。

## 写入

- 根 `AGENTS.md` 中没有 `## 个性化响应` 时，在文件末尾追加完整个性化响应段；恰好有一个同名标题时替换从该标题到文件末尾的内容，重复时停止写入。
- 任一文件无法安全修改时都不写。取消、沉默或含糊确认不写文件；普通对话中的风格反馈不自动积累。
