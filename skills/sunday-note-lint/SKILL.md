# Lint

## 工作流

1. 按固定 vault 布局建立 `30_知识库/` 全部 Markdown 清单，记录页面总数；维护日志只检查结构，不作为普通知识正文整理。
2. 用 `scripts/lint_headers.py` 检查全部 Wiki header；用 `scripts/audit_reachability.py` 检查 Wiki 导航及其指向 Raw / Routine 的链接，保存修改前基线。
3. 逐页阅读全部 Wiki，并按需读取直接相关的 Raw / Routine 证据；可将不同页面批次交给 subagent 做只读审计。每页标记为无需修改、需要维护或 blocked，不以脚本报告代替正文检查。
4. 完成逐页检查后，统一分析重复主题、可合并内容、冗余表述、矛盾或过期判断、页面边界、交叉链接、导航和 Raw 承接，整理为具体任务；同一目标页的问题合并为一个任务。
5. 完成全库审计后，汇总一份全局 Lint plan，列出本轮全部待执行任务、目标文件、动作、执行者、依赖、风险和验证方式；向用户输出后不等待确认。整轮维护共用这份计划，后续只更新任务状态，不按文件或修改重复生成计划。
6. 从全局计划按依赖和文件冲突分派任务。预计产生长文本、需要多轮工具调用或涉及跨文档读取与修改时交给 subagent；证据明确的单篇小段落删改可由主 agent 直接完成。每项完成后复核文件 diff、重跑相关检查并更新计划状态，再执行下一项。
7. 全部任务结束后重跑完整机械检查，核对清单中每页都有结论，所有低风险任务均已完成或已有明确 blocked 原因。
8. 只把已完成的内容新增、合并、重要修订或来源关系修复写入维护日志；最终报告页面总数、无需修改数、修改数和 blocked 数。

## 任务边界

- 用户明确要求只读、检查但不修改或禁止写入时，该约束覆盖默认授权：完成步骤 1–5 后停止，不分派执行任务，不修改文件，不写维护日志。
- 用户未限制写入时，调用即授权普通低风险维护。不确定结论、删除、归档、个人上下文和目标页不明确的任务标记为 blocked，继续执行其他任务，不在中途等待确认。
- Raw、Routine 只作为证据读取；Journal、Schema 不进入普通维护范围。
- `wiki_unreachable` 只通过 Wiki 导航关系处理，不把 Raw / Routine 加入 index。
- `raw_unlinked` 不由 Lint 直接写入 Wiki；将其作为独立的来源沉淀任务交给 subagent，明确来源文件和目标 Wiki，要求先判断知识增量再提炼或合并，来源文件保持不变。
- 主 agent 负责全库覆盖、任务拆分、计划输出、调度、复核和最终日志；只直接执行边界清楚的单页小改。
- subagent 只修改任务列出的文件，不修改维护日志；同一文件不会同时出现在多个未完成任务中。
- 无变更、blocked 和纯计划不写维护日志。

每个任务使用以下可直接发送的命令，不固化运行时参数：

```text
任务：
目标：
写入文件：
证据文件：
允许动作：
禁止动作：
验证命令：
返回内容：
```
