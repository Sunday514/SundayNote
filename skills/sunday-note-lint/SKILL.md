# Lint

## 工作流

1. 按固定 vault 布局建立 `30_知识库/` 全部 Markdown 清单，记录页面总数；维护日志只检查结构，不作为普通知识正文整理。
2. 用 `scripts/lint_headers.py` 检查全部 Wiki header；用 `scripts/audit_reachability.py` 检查 Wiki 导航及其指向 Raw / Routine 的链接，保存修改前基线。
3. 逐页阅读全部 Wiki，并按需读取直接相关的 Raw / Routine 证据；可将不同页面批次交给 subagent 做只读审计。每页标记为无需修改、需要维护或 blocked，不以脚本报告代替正文检查。
4. 完成逐页检查后，统一分析重复主题、页面拆分与边界、矛盾或过期判断、来源关系、核心导航、缺失知识承接，以及重复知识或需要实质提炼的内容。机械问题只进入最终报告，不生成写入任务。
5. 建立本轮唯一的全局 Lint plan；每项包含 `task_id`、知识问题、目标文件、证据文件、预期结果、执行者、依赖、风险、验证和状态。向用户输出后不等待确认；计划不再新增任务，执行中新发现的问题留到最终报告。
6. 所有计划内 Wiki 写入均交给 subagent。动作相同、文件不冲突、证据边界一致且验证方式相同的任务可以合并执行；每项完成后由主 agent 复核 diff、运行验证并更新计划状态。
7. 全部任务结束后重跑完整机械检查，核对清单中每页都有结论，并生成对照全局计划的最终报告：全库覆盖数、任务状态、实际修改文件、验证结果、blocked 原因、计划外新发现和机械诊断项。
8. 主 agent 在整轮结束时只写一次维护日志，记录全局计划中实际完成的知识维护、实际结果与计划的必要差异及最终验证结论。

## 判断边界

- Lint 处理改变知识状态的维护：主题合并或拆分、重要知识修订、跨页矛盾、来源关系、核心导航、缺失知识承接和实质提炼。
- Markdown 格式、header 格式、标点错字、断行排版、局部润色、无语义影响的链接写法和纯形式结构统一只报告。形式问题改变知识含义或破坏证据链时，按知识维护处理。

## 任务边界

- 用户明确要求只读、检查但不修改或禁止写入时，该约束覆盖默认授权：完成步骤 1–5 后停止，不分派执行任务，不修改文件，不写维护日志。
- 用户未限制写入时，调用即授权执行全局计划中的知识维护。不确定结论、删除、归档、个人上下文和目标页不明确的任务在计划中标记为 blocked，不在中途等待确认。
- Raw、Routine 只作为证据读取；Journal、Schema 不进入普通维护范围。
- `wiki_unreachable` 只通过 Wiki 导航关系处理，不把 Raw / Routine 加入 index。
- `raw_unlinked` 不由 Lint 直接写入 Wiki；将其作为独立的来源沉淀任务交给 subagent，明确来源文件和目标 Wiki，要求先判断知识增量再提炼或合并，来源文件保持不变。
- 主 agent 负责全库覆盖、语义审计、计划、调度、复核、最终报告和维护日志，不执行计划内 Wiki 写入。
- subagent 只修改任务列出的文件，不修改维护日志；同一文件不会同时出现在多个未完成任务中。
- 机械诊断、未执行任务、blocked、格式问题和无变化页面不写维护日志。

全局计划和 subagent 任务使用同一组字段：

```text
task_id：
知识问题：
目标文件：
证据文件：
预期结果：
执行者：
依赖：
风险：
验证：
状态：
```
