# Query

1. 先判断问题是否需要个人特定的长期项目、历史决策、目标、取舍或表达偏好；只有需要进一步了解这些个人信息时才读取根目录 `个人上下文.md`，普通事实或既有知识检索直接从问题提取检索线索。
2. 已读取的个人上下文包含准确 Wiki、Raw 或 Routine 入口时直接读取，并跳过第 3–4 步；不套用无关内容，也不用个人偏好改变来源事实。
3. 没有准确入口时，结合问题和已按需读取的个人上下文提取 3–8 个具体名称、日期、项目线索、术语或完整短语，运行 `scripts/query_search.py <关键词...>`，每个短语作为一个参数传入。
4. 运行搜索时，结合问题中的不同子主题和候选 `topic` / `keywords` 选择不超过 3 个 Wiki，按照主题相关性和重要性来选择；逐页读取，证据足够时立即停止。区分候选、精读后排除的页面和最终证据页面。
5. 已读取的入口或 Wiki 足够时直接回答。需要事实细节、项目验证、来源限制或冲突核对时，只读取 Wiki 直接链接的 Raw / Routine 文档，足够时停止，不递归跟随链接，不为确认存在性批量打开全部链接。
6. 只依据实际读取内容回答，不暴露 `%% agent ... %%` 注释块，不把来源结构复述当作知识，也不推断未确认的个人偏好或计划。
7. 对实际影响回答或承担来源路由的 Wiki 页面运行 `scripts/update_query_header.py <Wiki路径...>`；候选和排除页面不计数。用户要求只读时跳过；更新失败不阻断回答，只报告维护问题。
8. 不修改 Wiki 正文、index、根目录个人上下文或维护日志，不自动触发 Ingest、Lint 或 Audit。仅查询过程中产生稳定新知识时只提出写入建议。
