# Query

## 工作流

1. 从用户问题中提取 3-8 个关键词，优先保留用户对话中给出的名称、日期、项目线索、术语和短语；去掉泛词和任务动词。
2. 运行本 skill 的 `scripts/query_search.py <关键词...>` 获取候选文件列表。
3. 根据问题意图选择匹配度最高的候选作为证据文件：Wiki 看 `topic` / `keywords`，Routine 看日期、项目线索和命中词；证据文件不超过 3 个。
4. 读取证据文件，并以其内容作为证据回答问题；可使用 `%% agent ... %%` 注释块辅助理解，但回答用户时不暴露 agent-only 块，除非用户询问维护状态；不要粘贴大段搜索结果或原文。
   使用 Wiki 作为证据时，优先引用具体事实、判断、约束、经验模式、项目状态和已确认结论；不要把“本文 / 本章 / 本节 / 主要介绍”等来源结构复述作为证据。
5. 仅当本轮实际使用 Wiki 作为证据文件时，运行本 skill 的 `scripts/update_query_header.py <Wiki路径...>`，直接更新用到的 Wiki header：`last_queried` 写当天，`query_count` 加 1；同一页面每轮只计 1 次。脚本只改 YAML header，不改正文；header 缺失、损坏或 `query_count` 不是非负整数时，不强行修复，改为报告维护问题。
6. 问题回答后，如产生新的稳定判断、项目状态变化、兴趣方向、近期计划、推荐偏好或高价值总结，给出正文写回建议，并说明写回时需要更新目标 Wiki 的 `last_updated` 和 `update_count`；不直接写回正文。
