# Query

1. 从问题中提取 3–8 个具体名称、日期、项目线索、术语或完整短语，运行 `scripts/query_search.py <关键词...>`；每个短语作为一个参数传入。
2. 结合问题中的不同子主题和候选 `topic` / `keywords` 选择不超过 3 个 Wiki，按照主题相关性和重要性来选择；逐页读取，证据足够时立即停止。区分候选、精读后排除的页面和最终证据页面。
3. Wiki 足够时直接回答。需要事实细节、项目验证、来源限制或冲突核对时，只读取 Wiki 直接链接的 Raw / Routine 文档，足够时停止，不递归跟随链接，不为确认存在性批量打开全部链接。
4. 只依据实际读取内容回答，不暴露 `%% agent ... %%` 注释块，不把来源结构复述当作知识，也不推断未确认的个人偏好或计划。
5. 对实际影响回答或承担来源路由的 Wiki 页面运行 `scripts/update_query_header.py <Wiki路径...>`；候选和排除页面不计数。用户要求只读时跳过；更新失败不阻断回答，只报告维护问题。
6. 不修改 Wiki 正文、index、个人上下文或维护日志，不自动触发 Ingest、Lint 或 Audit。仅查询过程中产生稳定新知识时只提出写入建议。
