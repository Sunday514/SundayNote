# 知识库规则

## 目标

- 降低 agent 理解用户、项目和判断方式的成本。
- 维护可信、低摩擦、低熵的个人知识库。
- 优先保留个人增量和已确认判断，避免无确认的生成式污染。

## 知识库架构

### Raw 层

证据层，保存来源和未澄清材料；默认不改写。

- `10_原始材料/`: 证据、附件、截图、日志和未澄清材料。

### Routine 层

用户主导的过程记录层。

- `20_每日记录/`: 当天事实、过程、问题和简短总结。
- `21_每周记录/`: 周计划、复盘和阶段压缩。
- `22_每月记录/`: 月度方向、项目组合和阶段判断。
- `23_项目复盘/`: 项目状态、风险、下一步和复盘。

### Wiki 层

agent 可维护的长期记忆层。

- `30_知识库/`: 已确认、可复用、能减少未来解释成本的内容。

### Journal 层

用户本人表达层，默认只读。

- `40_个人写作/`: 用户写作和私人文字。

### Schema 层

规则、配置、模板和工具控制面。

- `AGENTS.md`、`CLAUDE.md`: agent 工作规则和兼容入口。
- `.agents/`: agent skill 导出目录。
- `.sunday-note-agent/`: 路径配置和自动化导出目录。
- `首页.md`: 知识库导航入口。
- `个人模板/`: 本地个人模板和相关自动化配置。
- `.obsidian/`: Obsidian 配置和运行状态；只修改明确需要维护的配置，不整理运行状态。
- `SundayNoteAgent/`: 可公开的工具项目；不要写入个人内容、个人模板正文或本地运行状态。

## 写入规则

- 不确定放置位置时，先放入 `10_原始材料/收件箱/` 或在对话中标记待确认。
- 修改正式笔记时优先追加或局部小改，保留人工内容。
- 新建正式页面前，先检查是否已有同主题页面可以更新。
- 不确定事实、推测和待确认内容要明确标记；没有可靠来源时不要编造。
- 长期引用的图像放在 `assets/figures/`，原始截图或临时图片先放入 `10_原始材料/`。
- Markdown 使用相对路径引用图像；图像默认显示宽度为 640，保持原始长宽比；移动或重命名笔记时同步修复图片链接。
- 日期统一使用 `YYYY-MM-DD`；Daily 文件名使用 `YYYY-MM-DD.md`，Wiki header 中的日期字段也使用 `YYYY-MM-DD`。

### Wiki 层

- `30_知识库/` 可由 agent 自动化维护。
- 只有包含个人事实、个人偏好、项目上下文、经验模式、历史决策或已确认判断的信息，才进入 `30_知识库/`。
- 网络搜索可替代的资料摘要、未经确认的 AI 总结、没有个人判断的摘录、当天流水账和临时命令输出不进入 `30_知识库/`。
- 写入时保留来源、相关链接和不确定性。
- Wiki 页面使用 YAML header：

```yaml
last_updated: YYYY-MM-DD # 内容或来源实质变化日期
update_count: 1 # 内容或来源实质变化次数
last_queried: "" # 最近一次作为 query 证据使用的日期
query_count: 0 # 作为 query 证据使用的次数
sources: [] # 长期可追溯来源，如书籍、课程、论文、网页
topic: "" # 单一稳定主题，用于判断页面归属和合并边界
keywords: [] # 检索提示词，用于 query 候选匹配
```

### Routine 层

- 以用户记录为主；agent 写入或改写前需要确认。

### Journal 层

- 默认只读；除非用户明确要求，不创建、修改、润色、移动、删除或自动搬运。

### Schema 层

- 只在用户要求维护规则、配置、skills、安装器或工具入口时修改。
- 修改前说明位置、理由和影响范围，并等待确认。
