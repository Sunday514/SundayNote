# 知识库规则

## 目标

- 降低 agent 理解用户、项目和判断方式的成本。
- 维护可信、低摩擦、低熵的个人知识库。
- 优先保留个人增量和已确认判断，避免无确认的生成式污染。

## 知识库架构

### Raw 层

外部证据层，保存论文、书籍、课程等资料的长期来源总结；忠实表达原有内容，不混入后续思考，默认不改写。

- `10_原始材料/`: 论文总结、读书笔记、课程总结、网页整理稿和其他可长期引用的来源总结。

### Routine 层

用户主导的过程记录层。

- `20_每日记录/`: 当天事实、过程、问题和简短总结。
- `21_每周记录/`: 周计划、复盘和阶段压缩。
- `22_每月记录/`: 月度方向、项目组合和阶段判断。
- `23_项目复盘/`: 项目状态、风险、下一步和复盘。

### Wiki 层

agent 可维护的长期知识层，也是默认 Query 入口。

- `30_知识库/`: 从 Raw、Routine 和已确认对话中提炼出的稳定、可复用知识。

### Journal 层

用户本人表达层，默认只读。

- `40_个人写作/`: 用户写作和私人文字。

### Schema 层

规则、配置、模板和工具控制面。

- `AGENTS.md`、`CLAUDE.md`: agent 工作规则和兼容入口。
- `.agents/`: agent skill 导出目录。
- `.sunday-note-agent/`: 路径配置和自动化导出目录。
- `首页.md`: 知识库导航入口。
- `个人模板/`: 本地个人模板和相关自动化配置。
- `.claudian/`: Claudian 本地设置和会话状态；不提交 sessions、设备 ID、CLI 绝对路径、环境变量或代理。
- `.obsidian/`: Obsidian 配置和运行状态；只修改明确需要维护的配置，不整理运行状态。
- `SundayNoteAgent/`: 可公开的工具项目；不要写入个人内容、个人模板正文或本地运行状态。
- `AGENTS.md`、`CLAUDE.md`、`.agents/skills/sunday-note-*`、已启用的 `paper-summarizer` 和 `.sunday-note-agent/quickadd/` 是安装器托管副本；不直接修改，应修改 `SundayNoteAgent/` 内对应源文件后重跑安装器。

## 知识流

```text
Raw / Routine ──Ingest──> Wiki
                           │
Query ──搜索 Wiki──────────┤
                           │
                           └──按链接读取 Raw / Routine

Lint ──检查 Wiki 结构、内容和向下链接
```

- Raw 和 Routine 是并列来源。Raw 总结外部资料，Routine 总结个人活动和项目验证。
- Ingest 读取 Raw / Routine，把稳定知识写入 Wiki，并在相关知识附近保留来源链接；不改写来源文档。
- Query 只搜索 Wiki；读取 Wiki 后，按问题需要读取页面链接的 Raw / Routine，不扩大搜索范围。
- Lint 检查 Wiki header、内容结构、Wiki 可达性和指向 Raw / Routine 的链接，不把 Raw / Routine 当作普通改写对象。
- Journal 不进入默认知识流，只有用户明确指定时才读取或处理。

## 写入规则

- PDF、docx、网页导出、解析中间产物和临时日志先放入 `.import_files/`。
- 外部资料完成忠实总结后放入 `10_原始材料/`；原始文件和解析过程产物留在 `.import_files/`。
- 修改正式笔记时优先追加或局部小改，保留人工内容。
- 新建正式页面前，先检查是否已有同主题页面可以更新。
- 不确定事实、推测和待确认内容要明确标记；没有可靠来源时不要编造。
- 长期引用的图像放在 `assets/figures/`，原始截图或临时图片先放入 `.import_files/`。
- Markdown 使用相对路径引用图像；图像默认显示宽度为 640，保持原始长宽比；移动或重命名笔记时同步修复图片链接。
- 涉及数学公式时，使用 Obsidian / Claudian 兼容 LaTeX：行内公式用 `$...$`，块级公式用独立的 `$$...$$`；不要使用 `\(...\)` 或 `\[...\]`。
- 日期统一使用 `YYYY-MM-DD`；Daily 文件名使用 `YYYY-MM-DD.md`，Wiki header 中的日期字段也使用 `YYYY-MM-DD`。

### Wiki 层

- `30_知识库/` 可由 agent 自动化维护。
- 只有能为未来回答提供知识增量的内容才进入 Wiki。相较直接使用 LLM、普通网络搜索或临时重读来源，能提高检索效率、回答深度或提供独特结构与见解，也属于增量；知识结构化本身可以构成增量。
- 论文、书籍或课程的来源忠实总结留在 Raw；基于一份或多份来源进一步思考形成的结构、关系、矛盾、方法框架、适用条件、个人经验和稳定判断进入 Wiki。
- 当天流水账、一次性安排、未验证猜测、未经提炼的摘录和临时命令输出不进入 Wiki。
- 优先更新已有同主题页面；新建页面的门槛高于局部更新。
- 在具体判断、方法、限制或项目应用附近保留 Raw / Routine wikilink；header `sources` 汇总页面级来源，初版不要求两者严格同步。
- 每份长期 Raw 最终都应至少被一个相关 Wiki 页面链接；没有 Wiki backlink 的 Raw 是 Lint 持续报告的覆盖缺口。Routine 只链接实际支撑稳定知识的记录。
- `30_知识库/索引.md` 只组织核心 Wiki 页面，不枚举全部 Raw / Routine。
- `30_知识库/知识库维护日志.md` 只记录真实执行的内容新增、合并、重要修订和来源关系修复；普通 Query、只读 Lint、blocked 任务、未执行建议和仅使用次数变化不写日志。
- 可在 `30_知识库/` 维护一个个人上下文页面，用于集中记录长期兴趣、近期计划、推荐偏好、当前项目和明确不感兴趣的方向；该页面只保存稳定、已确认、能降低未来沟通成本的信息，不归档完整对话或 Routine 流水。
- 个人上下文只在用户明确要求，或当前任务确实依赖个人偏好、计划和项目状态时使用；不固定输出推荐小节。
- 个人上下文页面的 `keywords` 用于记录真实兴趣词、方向词、项目词或常用问法，不用于标记页面类型；不要把“个人上下文”作为通用 keyword 加到相关计划或笔记中。
- 从对话、笔记或计划中发现新的稳定兴趣、近期计划、偏好约束或项目状态变化时，只提出写回建议；写入或更新个人上下文页面前需要用户确认。
- Wiki 页面使用 YAML header：

```yaml
last_updated: YYYY-MM-DD # 内容或来源实质变化日期
update_count: 1 # 内容或来源实质变化次数
last_queried: "" # 最近一次作为 query 证据使用的日期
query_count: 0 # 作为 query 证据使用的次数
sources: [] # 长期可追溯来源，如书籍、课程、论文、网页
topic: "" # 单一稳定主题，用于判断页面归属和合并边界
keywords: [] # 检索提示词，用于 query 候选匹配
```

### Routine 层

- 以用户记录为主；agent 写入或改写前需要确认。

### Journal 层

- 默认只读；除非用户明确要求，不创建、修改、润色、移动、删除或自动搬运。

### Schema 层

- 只在用户要求维护规则、配置、skills、安装器或工具入口时修改。
- 修改前说明位置、理由和影响范围，并等待确认。
