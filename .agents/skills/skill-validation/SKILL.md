# Skill 变更验证

把 Skill 视为可验证的行为资产。只保留由冻结场景证明有效的修改；结构更完整、规则更多或回答更长都不能单独证明改进。

## 1. 判断验证强度

修改以下内容时，必须运行与职责匹配的 baseline / candidate 对照验证：

- 触发条件、请求分类或 Skill 间路由；
- 可读取的来源、个人上下文或其他输入范围；
- 权限、确认点、写入目标或只读边界；
- 工作流顺序、失败分支或完成声明；
- 会影响行为的脚本、references、模板或默认参数。

排版、错字和不改变行为的链接修复只做静态检查。无法确定是否改变行为时，按行为修改验证。

## 2. 冻结验证契约

运行前记录：

- 被测 Skill、修改目标和预期解决的失败；
- baseline 与 candidate 的明确身份；
- 本轮唯一的主要行为变化；
- 允许声明的改善及其验收条件；
- 冻结的用户消息、来源包、个人上下文、工具权限和上下文继承方式。

不得根据 candidate 输出反向修改场景、参考事实或验收标准。运行中发现需要继续修复时，结束本轮；修改后建立新的 candidate 并重新验证。

至少冻结三个真实场景：

1. 最典型的正常请求；
2. 本次修改针对的已知失败；
3. 不应受修改影响的负向对照。

验证写入型 Skill 时，按修改职责补充无增量拒写、多页写入确认、Raw 只读、canonical 页面选择和写入后查询复用场景。

## 3. 运行对照

对同一冻结请求分别运行 baseline 和 candidate。除被测 Skill 外，保持模型、用户消息、来源材料、个人上下文、工具和文件初始状态一致。

- 使用 fresh subagent，不继承当前开发对话、历史结论或另一个候选的输出。
- 只向生成 subagent 提供任务所需的 Skill、冻结来源包和工具权限；不提供组别、评审标准、参考答案或修改理由。
- 需要文件操作时使用临时 vault 或通用 fixture；父 vault、开发仓库和另一候选保持不可写。
- 默认禁用 web、额外 MCP、记忆和其他 Skill。任务确实需要时，对两组提供相同能力并写入输入清单。
- 保留完整用户消息、回答、文件 diff 和机械指标。Query 计数 header 不算知识增量。

若两组存在无法解释的输入差异，停止比较并重新运行，不用评分修正污染。

## 4. 匿名评审

Judge 使用未参与生成或修复的 fresh subagent，不继承开发对话。

1. 用匿名 ID 替换版本、session 和工作区信息。
2. 先逐个评审候选，再在需要时成对比较。
3. Judge 只接收当前候选的完整对话、知识 diff、冻结意图、允许来源和机械指标。
4. 分别检查：
   - 来源忠实度、事实错误和越界推断；
   - 知识增量、页面选择、来源关系和后续复用；
   - 对话明确性、用户偏好匹配和无关个性化。
5. 不以篇幅、术语数量、格式复杂度或单一总分代替行为判断。

Judge 分歧会影响接纳结论时，使用两个 fresh session 做相反展示顺序的复核。顺序改变结论时，将该项记为不确定。

## 5. 硬失败

出现以下任一情况时，不得声明修改有效：

- 使用无来源的关键事实、错误归因，或把跨领域类比写成直接证据；
- 未经确认扩大写入范围，修改 Raw、父 vault 或无关文件；
- 没有契约允许的知识增量、来源关系维护或 Query 计数更新却制造修改；来源关系维护超出相关 wikilink 和必要 header，或 Query 计数更新带动其他文件内容变化，也按硬失败处理；
- 损坏已有知识、来源关系、链接或可检索入口；
- 负向对照在事实、来源、写入或复用能力上退化；
- 生成候选或 Judge 看到了禁止输入，盲态失效；
- baseline 与 candidate 除被测 Skill 外存在无法解释的输入差异。

文件越界、网络访问或真实 workspace 写入作为 containment 失败单独记录。发生 containment 失败时，可以保留对话作为行为线索，但不能声明修改已经通过验证。

## 6. 接纳修改

只有同时满足以下条件，才能声明行为修改有效：

- 没有硬失败或 containment 失败；
- 目标场景产生明确、可解释的改善；
- 典型场景和负向对照不退化；
- 改善来自预期机制，而不是增加篇幅、规则数量或格式复杂度；
- 验证证据足以支持声明强度。

证据不足、Judge 结论不稳定或只能干跑推演时，记录为未验证。是否暂时保留修改由用户决定，不得表述为已经有效。

## 7. 输出验证记录

验证结果至少包含：

- 被测 Skill、修改目标、baseline 和 candidate 身份；
- 冻结场景与两组实际输入清单；
- 完整候选回答、知识 diff 和机械指标；
- 硬失败与 containment 检查；
- 匿名评审和必要的顺序复核结论；
- 已证明、未证明和必须重跑的范围。

验证产物放在临时目录或通用 fixture，不写入父 vault、开发计划或开发日志。只有形成稳定、脱敏、可迁移的回归场景后，才将 fixture 保存到本仓库。
